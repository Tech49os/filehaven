## 块① 补修：窗口四周 8px 透明带（`db41549`）

- 现象：窗口内容外一圈约 8px 灰色渐变带（外侧 227 → 内侧 172），用户称「透明的边，很明显」。
- 根因：**不是 CSS**。`tauri.conf.json` 的 `"shadow": true` 让 tao 为画 DWM 投影把窗口各向外扩 8px（上 1px），WebView2 只覆盖客户区；`transparent: true` 下这圈没内容 → 显示桌面 + 阴影。
- 实测：WindowRect 1176×749 vs ClientRect 1160×740，pad=(8,1,8,8)。
- 四种 Win32 手段全部无效：`DwmExtendFrameIntoClientArea{0,0,0,0}`、移除 `WS_THICKFRAME`、换 `WS_POPUP`、`NCRENDERING_POLICY=DISABLED` —— 外扩在窗口创建时就定了，只能改配置。
- 修复：`shadow: true → false`；`ui-window.test.ts` 加契约测试（JSON 导入，**项目无 @types/node，测试里不能用 `node:fs`**，vue-tsc 会报 TS2307）。红测验证：临时改 true → 失败，改回 false → 通过。
- 结果：WindowRect=ClientRect=1160×740，pad 全 0，截图 1160×740；左/上/右/下边缘只剩 1px 描边抗锯齿。
- 代价：窗口失去 DWM 投影（边缘直接切桌面）；`WS_THICKFRAME` 仍在（style 0x14CF0000），缩放能力保留。
- 复验命令：`python test/shotp.py <out.png>` 后采样四边像素；CDP 截图对透明窗口不可信（会把透明区渲成白色）。

**新硬经验 —— core.autocrlf 会让 CSS 字符串断言静默失败**：
- 现象：合并后 `git checkout main`，BUG-005 的 `cssRule(src, '.left,\n.right')` 返回空串 → `toMatch(/overflow:auto/)` 失败。
- 根因：`core.autocrlf=true` + 无 `.gitattributes` → 检出时 .vue 变 CRLF（`git ls-files --eol` 显示 `i/lf w/crlf`）；测试里写的是 `\n`。

- 修法：① helper 先 `replace(/\r\n/g,'\n')` 再匹配（补 2 条 CRLF/LF 双路自测）；② 加 `.gitattributes`（`* text=auto eol=lf`）从根消除。
- 教训：**任何按换行断言源码的测试都必须归一化行尾**，否则只是在该机器该分支上碰巧成立。

**踩到的坑（新）**：
- **GitHub 会静默剥掉资产名里的非 ASCII 字符**：上传 `文件管家_v0.7.0-alpha.1.exe` 得到
  `_v0.7.0-alpha.1.exe`（中文全没，只剩下划线和后半段），HTTP 依然 201 uploaded，不报错。
  资产名一律用 ASCII，中文放 `label`（`upload.py` 的 `name`/`label` 两个字段）。
- **删除资产不是 `/releases/{id}/assets/{asset_id}`**，正确端点是 `/releases/assets/{asset_id}`。
  挂在 release 下面会返回 404 Not Found，看起来像没权限，其实路径错了。
- **`git credential fill` 能直接拿到已有 token**（`username=x-access-token`），不必让用户重新授权；
  `X-OAuth-Scopes` 里有 `repo` 就能建 release 传资产。
- 上传走 `uploads.github.com`，下载重定向到 `objects.githubusercontent.com`，
  本机 8.4MB 约 97s（慢但稳定），大文件上传要有耐心别中途断开。
