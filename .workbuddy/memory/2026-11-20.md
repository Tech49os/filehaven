# 2026-11-20 · P1 首次实测反馈修复（alpha.2）

用户实测 v0.3.0-alpha.1 后给的三条反馈 + 我查出的第四个问题，全部修完并出包。

## 四条问题的真因（写给下次的自己，别重复猜）

1. **源区移除后加不回来** —— 不是状态机问题，是 Settings 源区卡片**没有添加入口**
   （只有「移除」「重新扫描」）。Onboarding 里有，但 `App.vue` 一旦 `configured`
   就把 `/onboarding` 重定向回 `/workspace`，等于永久锁死。
   修法：卡片头加「添加源区」+ 空态加「选一个文件夹」，两处都能点。
   `Settings` 进页时补 `if (!app.ready) refreshBoot()`，否则深链/刷新会显示成
   「还没有源区」而库里其实有。

2. **点扫描弹黑框一闪** —— `free_gb` 用 `Command::new("powershell").output()`。
   GUI 进程（`windows_subsystem="windows"`）起控制台子进程**必然弹黑框**。
   所有查空间的路径都会闪：设置页一进、选归档区、迁移预演、扫完刷新。
   修法：`GetDiskFreeSpaceExW`（`windows-sys` 0.61，本来就在 Cargo.lock 里，
   加 feature 而已）。微秒级、零子进程。
   **经验：以后任何时候怀疑「不明黑框」，先 grep `Command::new`。**

3. **卡滞** —— 两个真卡点，不是动画问题：
   - `boot_state` 里同步做 3s 模型探活，而 `refreshBoot()` 在**每次判定后**都调。
     等于每按一次回车停一下。修法：`boot_state(probe_model)` + `AppState.model_reachable`
     （AtomicBool）缓存，只有启动首调与设置页「重新检测」真探活。
   - 侧栏/标题栏 `backdrop-filter` 底下就是窗口自己的纯色 `--c-bg`，
     blur 纯色视觉零收益、每帧要合成。换不透明色 `--c-sidebar:#f2f2f7`
     `--c-titlebar:#f6f6f8`，目视无差别。
   动效只加必要的：路由 140ms 淡入上浮（`mode="out-in"`）、换卡淡入
   （靠 `:key` 重挂 + CSS animation，不用 `<Transition>`，否则容器塌一下、
   快捷键行会跳）、确认结果条浮入、已确认列表 stagger、按钮按压 0.97、
   `prefers-reduced-motion` 兜底。

4. **（顺带）`save_note` 后端没注册** —— 整理台「先放着 → 双击写备注」点了
   报「命令不存在」。`ipc.ts` 里有一堆命令（list_parked/browse_dir/search_files…）
   后端压根没实现，P2 才补。已补 `index::set_note` + `save_note` 命令。
   **待办：P2 开工时先按 ipc.ts 清单把已声明未实现的命令对齐一遍。**

# 2026-11-20 11:40 · 第二轮实测反馈（alpha.3）

用户继续反馈三条：①AI 目录推荐没法表达主观意见；②整理台只看得到文件名，路径/内容看不到、
不能快速打开；③非最大化时排版挤。全部做完出包 alpha.3。

## 三条的真因

1. **没法把意见喂给模型** —— 不是模型不听话，是**根本没有入口**：
   `suggest_dirs` 命令入参只有 `force`（换一批样本），prompt 里只有文件与已有目录。
   「换一批」= 换样本重跑同一套逻辑，所以感觉是空转。
   修法：加 `hint`（`normalize_hint`：换行压空格、200 字上限、空白→None）；
   prompt 在样本行之前插一段「他额外提了补充要求…优先满足」；`hint=None` 时 prompt
   与旧版**一字不差**（有测试盯着，T5.8 的实跑结论不能被悄悄改掉）。
   另加：方案里每个目录可**就地改名/删除/自己加一条**（改名走 `preview_dir_name`
   就地校验，非法名标红且禁止提交），采纳时传改过的名字。
   还补了**入口**：设置页「AI 建议目录」→ `/onboarding/dirs`。之前配置完成后
   `App.vue` 会把 `/onboarding` 重定向走，那页等于一次性用完就消失，想换分法只能删库。

2. **看不到路径和内容** —— 卡片里其实渲染了 `relPath`，但塞在
   「大小·类型·时间·路径」一行的末尾，被省略成只剩文件名；`absPath` 后端一直有传、
   前端从没用过。正文预览和打开按钮完全不存在（`open_path`/`reveal_path` 早就有，没人调）。
   修法：新增 `preview_file` 命令 + `preview.rs`（复用 P0 写好但从没接线的 `extract`，
   补了 zip/flate2/regex 依赖 + `#[allow(dead_code)] mod extract`）：
   正文 700 字上限、图片只回 `kind=image`（缩略图走 asset 协议，不在后端解码）、
   PDF/读不出正文时给一句人话原因。卡片加完整路径行 + 「打开(O)」「定位(L)」+
   摘要块（4 行 clamp + 展开）+ 图片缩略图。前端按 fileId 缓存，一份文件一次会话只读一次。

3. **非最大化时挤** —— 算出来的硬约束：窗口 1160 − 侧栏 200 − 内容边距 48 −
   两栏 208×2 − 间隙 28 ≈ **中间卡片只剩 468px**。
   修法：`useNarrow`（matchMedia 1240px）→ 窄窗右栏变抽屉（顶部「已确认 N」开合）、
   左栏收 176、侧栏收 176，卡片宽度回到 **760px**；`tokens.css` 按窗口尺寸分档收边距
   （≤1240 → 18/18，≤800 高 → 14/16）；卡片 `flex:1` 吃满高度，按钮固定贴底
   （键盘流的位置稳定，比卡片浮在灰底上强）。

## 顺手改的一条门槛（重要，别再改回去）

`validate` 现在**两级**：先按「每目录 ≥2 份支撑」(V2)，过不了退回「≥1 份」再判。
真因：小语料（12 份）凑不出 6 个目录 × 每个 2 份，实测 4b/9b 连续多次被 V2 整份扔掉，
用户白等 40~240 秒什么都拿不到 → 直接掉到手写。引用 1 个**真实存在**的样本不算编

兜底不放水：越界序号、泛词目录名照样剔（有测试）。

## 第三轮反馈（14:05 收到，15:0x 出 alpha.4）

七条，按「真因 → 改法 → 证据」记。提交 `c215bf1`，产物 `发布/文件管家_v0.3.0-alpha.4.exe`。

### 1. 42MB pptx 说「读不出正文（可能是扫描件、空文档或加密文件）」
- 真因：`extract::extract` 开头 `if size > MAX_PARSE_BYTES(30MB) return 空`。
  42MB 里几乎全是图片/视频，slide XML 只有几 KB —— **按总大小一刀切**。
  （MEMORY.md 里早就写过这个坑，但 `extract` 这条闸一直没改，属于「记了没落地」。）
- 改法：体积闸只留给 drawio（整份 read_to_string）；Office 走 `MAX_ENTRY_BYTES = 8MB`
  的按 entry 限读。老版二进制 `.doc/.ppt/.xls/.wps` 单独提示「这版解析不了」，
  不再说成「你的文件可能是扫描件/加密」。
- 证据：单测 `huge_pptx_is_still_readable`（size 传 42MB，真 pptx 断言抽到正文）红→绿；
  e2e 加了一份真 pptx，卡片上读到「生产智能化项目组工作汇报 …」。

### 2. 已确认态「文字和边框距离有问题」
- 真因：不是内边距小，是上一轮我把卡片改成 `flex:1 0 auto` 让它吃满高度，
  内容少时就成了「上面挤一堆、下面一大片白」。用户看到的「距离不对」是这个失衡。
- 改法：`.mid :deep(.card){flex:0 0 auto}`（按内容高）+ 内边距 20/22（矮窗 16/18）。
- 证据：CDP 量到真实 `padding: 16px 18px`，ico/pathrow 相对卡片 left 内缩 19px；
  已确认卡实测 760×191（不再是整列高）。
- **教训**：用户说「间距不对」时，先用 CDP 读 `getComputedStyle` + `getBoundingClientRect`，
  别拿截图猜 —— 我这次在截图像素上算了半天，把卡片左边缘认错了 17px。

### 3. 「还没有任何目录」1009×241 虚线块
- 真因：它不是空态，是**叠在已经完整可用的整理台上**的额外一块（条件只判了 dirCount===0）。
- 改法：换成一行 `.nodir` 提示条（图标 + 一句 + 两个按钮），候选区的「先按 N 建一个」照旧。

### 4. 每次进整理台都刷新 + 「第 N 批」
- 真因：`onMounted` 无条件 `store.load()`。
- 改法：`ensureLoaded()` —— 有批次就接着用；`closed`（结束本批）才重开。
  **坑**：空批次不算有批次（`items.length > 0` 才算）。启动时池里没文件，那次 next_batch
  是空的，不重开就永远停在「池子里没有待整理的文件」—— e2e 第一次跑就是这么挂的。
- 文案：头部改「待确认 N 份」，去掉第几批；队列行不再每行重复「待确认」。

### 5. 目录不能复用到下一份
- 用户原话要的是两件事：新建目录后**后面那些文件要能重新推荐**，且 N 输入框要有联想。
- 后端 `rescore_files(file_ids)`：按现在的目录集合重算候选，只换 candidates/needsYou，
  不动顺序/状态/焦点（换整批会让已确认的重新跳）。新建目录后自动调，另有「重新推荐」按钮。
- N 输入框：`<datalist>` 换成自己画的下拉（WebView2 里 datalist 中文输入基本弹不出来）；
  ↑↓ 选、回车直归已有目录（`create_dir` 逐段查重，本来就不会建重复目录）。
- 坑：`syncDirCount` 只该在「原来 0」时修 —— 每次挂载都覆盖会把手上的 dirCount 冲掉，
  测试里正是这么炸的（mock 的 listDirs 返回 []）。

### 6. 确认前改名
- `files.target_name`（`PRAGMA table_info` + `ALTER TABLE` 幂等补列，老库可用）；
  `plan::clean_file_name` 保扩展名（不丢不叠）；`index::effective_name` 供迁移用。
- 卡片铅笔 → 输入框只放主干、扩展名固定显示；改过就常驻「归档时存为 …」+ 还原。
- 待迁移列表显示目标名并标「改名」。
- **顺手修的错位**：`confirmed_for_migration` 里目录两列偏移写死 `12/13`，加列后读成 NULL
  直接炸 6 个迁移测试 → 改成由 `FILE_COLS` 列数算偏移。

### 7. 定位打开的是文档目录
- 真因：`/select,<路径>` 当普通参数给 `Command::arg`，含空格时整段被加引号，
  explorer 认不出 → 不报错、回落默认目录。
- 改法：`raw_arg` + `/select,"路径"`，抽成 `explorer_select_arg()` 并单测引号形态。
