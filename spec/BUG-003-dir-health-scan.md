## 1. 问题陈述

用户原话：「当前存在目录建错或者是重复含义的目录，应该有 AI 智能扫描，然后推荐修正策略。」

现状证据：
- `create_dir`（`main.rs:451-488`）逐段 `dir_by_rel_path` 查重，只认完全相同路径。
- `NewDirInput.vue` 建议列表按 `relPath` 子串过滤，只防「一模一样」的重复。
- `suggest_dirs.rs:292-301` 只在**生成方案时**写提示词「不要另起同义目录」，对已建目录无检查。
- 命令表（`:2421-2468`）没有 `rename_dir` / `merge_dir` / `dir_health` 一类命令。

## 2. 目标 / 非目标

**目标**
- 提供**手动触发**的「目录体检」：扫描已有目录，输出问题清单与修正建议（重命名、归并、层级调整、空目录），每条带依据。
- 用户对建议逐条「采纳 / 忽略」；采纳后走既有批次与撤销体系。

**非目标**
- 不自动改动目录；不做任何静默迁移。
- 不直接删除磁盘目录或库记录（与 BUG-006 的合并共用底座，但本 spec 聚焦「建错/结构异常」；语义等价合并由 BUG-006 覆盖）。
- **绝不把扫描挂进 `refreshBoot()` 默认路径**——它在每次判定后都会被调（项目铁律）。

## 3. 行为规格

1. **Given** 用户在浏览页或设置页点击「目录体检」，**When** 扫描启动，**Then** 先用确定性规则筛选候选（空目录、超深层级、名称含版本/草稿后缀、路径段高度相似），再在模型可用时提交 LLM 复核。
2. **Given** Ollama 不可用或 `ModelGate` 被占用，**When** 扫描，**Then** 降级为只输出规则确信的候选，并在报告中标注「未经模型复核」，不得阻塞或报错退出。
3. **Given** 扫描结果含多条建议，**When** 展示，**Then** 每条给出 `kind`（rename/merge/move/empty）、`dirId`、目标路径、理由、置信度、影响文件数；用户可逐条采纳或忽略。
4. **Given** 用户采纳一项重命名/移动，**When** 执行，**Then** 生成批次记录与前后路径，受影响的已归档文件 `archived_path` 同步更新，操作可按批次撤销。
5. **Given** 目标目录已存在同名文件，**When** 执行，**Then** 按既有 `unique_name` 规则错开，绝不覆盖。
6. 扫描过程发出阶段事件（scan → rule → model → done），前端显示进度；耗时操作不冻结 UI。

## 4. 变更点

- 后端新增 `dir_health_scan` 命令 + 结果模型（建议放 `app-v2/src-tauri/src/dir_health.rs`，`main.rs` 注册）。
- 复用 `suggest_dirs::run` 的「抽样 → prompt → JSON 容错解析 → 门槛校验 → 阶段事件」骨架与 `ModelGate`；复用 `plan::clean_path` / `strip_version_suffix` / `is_filler_composed` 做确定性预筛。
- 修正执行优先复用 `migration.rs::recategorize` 与批次 `undo`；若需新增 `rename_dir` 命令，必须更新 `archive_dirs.rel_path` 及所有后代路径，并写审计记录。
- 前端在设置页加入口与建议列表（沿用 `Card.vue` 与 BUG-010 的滚动约束）。

## 5. 验收标准（先写红测）

- [ ] Rust 单测：构造空目录、同义路径、超深层级样例，规则层全部识别且无误报。
- [ ] Rust 单测：模型不可用时返回降级报告而不是错误；`ModelGate` 占用时不死锁、不抢深读模型。
- [ ] Rust 单测：采纳建议后 DB 路径与文件 `archived_path` 一致；撤销后完全还原；同名冲突不覆盖。
- [ ] 前端单测：建议列表逐条采纳/忽略，忽略项不进入执行批次。
- [ ] e2e：手动点击体检 → 看到建议 → 采纳一项 → 目录树更新 → Ctrl+Z/撤销按钮还原。

## 6. 风险与边界

- LLM 可能把项目背景当归口（项目既有教训）：建议必须**可解释、可拒绝**，绝不静默执行。
- 一次扫描候选过多时：限制单次输出条数（建议 ≤20），超出分页或按置信度截断。
- 目录重命名涉及子树路径批量改写，属于高风险写操作，必须先写事务与回滚测试。
- 模型独占显存；避免与深读队列并发抢闸。
