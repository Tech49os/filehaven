| 项 | 值 |
|---|---|
| 来源 | `bugfix/20261122_bug_feedback_001.docx` 第 4 条 + 截图 5（红圈「务要*」） |
| 确认结论 | **部分属实**：「务要」是 2-gram 跨词切分产物；「服务委托书」是 AI 弱标签；Word/2026/2026-Q4 是刻意设计的基础标签（按用户裁决保留） |

| 测试落点 | `app-v2/src-tauri/src/tests.rs:390-409`（已有基础标签断言） |

## 1. 问题陈述

用户原话：「标签打的有一些问题，有一些根本就不是词汇。」

截图 5 中标签依次为 `Word`、`2026`、`2026-Q4`、`务要*`（红圈）、`服务`、`服务委托书`。逐类核对：

| 标签 | 来源 | 判定 |
|---|---|---|
| Word / 2026 / 2026-Q4 | `tag.rs:244-262` 基础标签 | 产品设计，用户裁决保留，不改 |
| 务要 | `tag.rs:123-148` 汉字段 2-gram | **伪词，需治理** |
| 服务委托书 | `deep_tag.rs` AI topic | **弱标签（文档体裁），需治理** |

根因：
```rust
// tag.rs:142-147：4 字以上汉字段除整段外逐字生成 2-gram
push(seg.clone(), &mut out);
for i in 0..n - 1 { push(c[i..i+2].iter().collect::<String>(), &mut out); }
```
「服务要求…」被切成「服务」「务要」「要求」，其中「务要」跨词边界。`STOPWORDS` 只有 22 条，无法覆盖。AI 侧 `GENERIC` 只有 12 个泛词，`clean_tags` 不做体裁判断。

## 2. 目标 / 非目标

**目标**
- 新生成的 keyword 标签不再出现跨词边界的 2-gram 伪词。
- AI topic 标签过滤「文档体裁/类型名」类弱标签（委托书、说明书、合同、表格等）。
- 已落库的脏标签有一次性清理路径。

**非目标**
- 不改 type/time 基础标签（`Word` / `2026` / `2026-Q4`）。
- 不引入中文分词词典/词库（原设计明确拒绝，见 `tag.rs:5-12` 注释）。
- 不覆盖 `tag_locked=1` 的人工标签。

## 3. 行为规格

1. **Given** 文件名含 4 字以上汉字段，**When** 生成 keyword 标签，**Then** 保留整段词元，**不再生成跨边界 2-gram**；2–3 字整段规则不变，纯数字与单汉字继续丢弃。
2. **Given** AI 返回「服务委托书」这类体裁/类型词，**When** `clean_tags` 后处理，**Then** 该词被过滤；prompt 同时明确禁止「文档体裁名」。
3. **Given** 库中已有 keyword 伪词或弱 topic 标签，**When** 运行一次性清理任务，**Then** 删除对应 `file_tags` 行；人工锁定（`tag_locked=1`）的标签保留。
4. **Given** 清理后重新扫描同一文件，**When** 生成标签，**Then** 不再重新产生相同伪词（回归防护）。
5. 标签展示顺序与主题色不变；用户手动增删标签能力不变。

## 4. 变更点

- `tag.rs::tokenize`：删除 2-gram 生成循环；保留整段与既有停用词预处理。用测试锁定「服务要求说明书」不产生「务要」。
- `deep_tag.rs`：扩展 `GENERIC` 黑名单并新增体裁词判定（可用后缀/整词匹配，不引词库）；prompt 第 2 条补「不要输出文档体裁/文件类型名」。
- 新增一次性清理命令（建议 `clean_bad_tags`），按规则扫描 `tags` 表中 keyword/topic 记录；尊重 `tag_locked`。
- `tests.rs` 中原有基础标签断言保持通过，只改伪词相关预期。

## 5. 验收标准（先写红测）

- [ ] Rust 红测：`tokenize("服务要求说明书")` 结果不含 `务要`；仍含合理整段词。
- [ ] Rust 红测：`clean_tags` 过滤 `服务委托书`、`说明书`、`通知书` 等体裁词；保留真正的主题词。
- [ ] Rust 红测：清理任务不删除 `tag_locked=1` 的标签；重扫不再生成伪词。
- [ ] 回归：`tests.rs:390-409` 基础标签断言（Word/年/季度）继续通过。
- [ ] e2e：截图 5 中同一份文件重新扫描后，标签区不再出现「务要」，仍可见 Word/2026 基础标签。

## 6. 风险与边界

- 去掉 2-gram 会降低长文件名的关键词召回；整段词与 AI topic 仍覆盖主要语义，若实测召回明显下降，再考虑「白名单式 2-gram」而非全面恢复（需另开 spec）。
- 清理任务必须幂等，重复运行不报错、不误删用户标签。
- 不动 `rename_tag` 的撞名合并语义。
