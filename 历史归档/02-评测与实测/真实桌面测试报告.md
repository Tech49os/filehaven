## 二、第一版引擎的失败（以及为什么值得记录）

### 现象

```
采购商务建议书        → 风控系统 (99%)     ← 应为商务采购
差旅费审批单          → 用户中心 (99%)     ← 应为财务报销
绩效考核指标          → 支付系统 (99%)     ← 应为部门管理
安全检查报告          → 用户中心 (99%)     ← 应为安全合规
```

**450 个文件里，"支付系统""用户中心""风控系统""订单系统"这些分类根本不存在于你的业务中。**

### 三个根因

1. **词典是错的**：MVP 用的示例词典是电商主题（支付/订单/风控/用户中心），与海油智能工厂业务零重叠。
2. **置信度是假的**：v1 的公式只看"得分与得分差距"，关键词偶然命中就给 99%。这是**比不分类危险一百倍**的行为——界面上的绿色徽章告诉用户"AI 很确定，放心接受"，于是用户会批量接受错误结果，把 450 个文件迁进错误目录。
3. **命名在销毁信息**：`差旅费审批单.docx` 被重命名为 `2026-11_权限_运维手册_v1.docx`。原名信息全丢。

### 一句话教训

> **"AI 说不确定"是可接受的产品行为，"AI 极其确定地搞错"是产品事故。**
> 置信度必须由"是否有硬证据"决定，不能由"分数算出来是几"决定。

## 三、为真实语料重建的四件事

### 1. 分类体系从你的语料归纳，而不是我预设

你的文件天然按**项目/工作线**组织（这是你脑子里真实的索引方式），所以一级分类改成「工作域」：

| 一级（工作域） | 二级（文档类型） |
|---|---|
| 智能工厂平台 | 方案设计、汇报材料、会议纪要、制度规范、参考素材 |
| 钻采院项目 | 方案设计、成本报价 |
| 油化厂项目 | 成本报价、汇报材料 |
| 部门管理 | 考核人事、制度规范、汇报材料、方案设计 |
| 商务采购 | 合同协议、成本报价 |
| 人事培训 | 考核人事、方案设计 |
| 财务报销 | 单据表单、成本报价 |
| 安全合规 | 检查应急、制度规范 |
| 知识沉淀 | 参考素材、汇报材料、方案设计 |

### 2. 置信度改为「证据锚定」

- 没有核心证据词 → **一律封顶 0.62**，必进待确认
- 证据只承认**文件名里的词**（正文命中只贡献分数，不算证据）
- 证据分三级：文件名硬证据 0.86+ / 正文推断 0.78 / 主干兜底 0.74 / 无法判断 0.55
- 归错二级类型只微降置信度（文件还在正确项目里），归错工作域才致命

### 3. 正文权重按"谁更需要"分级

- **工作域**：正文权重 0.10（几乎只听文件名）
  - 因为作者命名时必定带项目名，而正文里出现什么词不代表归属
  - 反例：一份精益管理的流程表，正文里写满"合同管理""商务落地""成本"，若给正文权重就会被判成商务采购
- **文档类型**：正文权重 0.35
- **辅助词累加封顶 2.5**（防「方案设计」这种词条多的分类靠堆泛词获胜）

### 4. 新增"文件名没信息时看正文"的降级通道

这是**你这类用户最需要的功能**——`final_v2.docx`、`新建文档.docx`、`实验模块.xlsx` 这种文件名毫无信息但正文清清楚楚的文件。

- 文件名有证据 → 只信文件名（高置信）
- 文件名无证据 → 用正文判断，但置信度打折（0.78，黄色），提示"依据正文判断，请扫一眼"
- 这样救回 **33 个文件**，且不引入正文污染

## 六、当前局限（诚实清单）

| 局限 | 影响 | 原因 | 解决方向 |
|---|---|---|---|
| **PDF 正文未抽取** | 44 个 PDF 只靠文件名判断 | 未实现 PDF 文本层解析 | 接 pdf 解析库；扫描件需 OCR |
| **图片无法判断** | 17 个图片全部进待确认 | 需视觉模型 | 接 CLIP（约 110 MB） |
| **大文件跳过正文** | >30 MB 的 PPT 只用文件名 | 避免读 690 MB 卡死 | 分块读取 slide XML |
| **二级类型 85%** | 少数类型会判错 | 规则抓不住"演讲稿算汇报材料"这类语义 | **必须上本地 LLM**（Qwen2.5-3B） |
| **词典需人工维护** | 新项目名要手动加词 | 规则引擎的固有成本 | LLM 可零样本识别新项目 |

### 一个必须说清的事实

这轮测试**再次验证了之前的判断**：纯规则/统计方法的上限就在 **85% 左右**，再往上必须依赖语义理解。

- 工作域能到 93%，是因为"项目名一定写在文件名里"，规则抓得住
- 类型只有 85%，是因为"演讲稿算不算汇报材料"需要语义理解，规则抓不住

**所以技术设计文档里"本地 LLM 做语义理解"的选择不是过度设计，是必要项。**
