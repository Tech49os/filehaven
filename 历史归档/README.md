## 二、走过的三条路，各自的死因

| # | 路线 | 做到什么程度 | 为什么停 |
|---|---|---|---|
| 1 | **固化词典分类**（9 工作域 × 10 类型，纯规则打分） | v0.1 ~ v0.2.1 主线，64ms 跑完 450 份 | 类目表是拍脑袋定的：178 份（39.5%）全挤进「智能工厂平台」；96 份判不出。**真实在办的事（技术谱系、AI 大赛、中期工作会、梯度培育…）系统里根本没有对应类目**，怎么判都错 |
| 2 | **规则 + 本地大模型混合**（双路一致才直通） | 45 份送模型 / 155s，一致 30 份直通、待确认 280→262 | 收益太薄（净减 18 份），代价是 3s/份 + 显存调度。**模型会把正文里的项目背景当归口**（正文出现「智能工厂平台」→ 安全检查报告/费率清单全归过去，真实 5/5），分歧不可采信，只能靠规则兜 |
| 3 | **涌现式分类**（从文件名提候选专名 → 保守分组 → 模型只判「是不是人名/机构名」→ 人确认 → 分层建目录） | 45 正经类 + 5 兜底类，归类 318/455（70%）；47 个版本族已折叠；测试 223 全过；分域由 9b 一次性给出 4 个大类（83s） | **用户实测判定「还是不尽人意」**。硬伤：未归类死守 30%、泛词/碎片类（`平台技术室`、`发展智能工厂系统`）要人工删、生成方案要等 2 分钟 |

三条路的共同教训：**从文件名猜「这份文件属于哪件事」，在真实语料上最多到七成**。剩下三成的文件名就是没有事项信息（`IMG_2034.jpg`、`附件2.pdf`、`新建文档.docx`），再换算法也变不出来。

## 三、可直接复用的结论（新方案别再踩一遍）

### 3.1 环境事实

- Node v22.22.2 / npm 10.9.7；Rust 1.100.0（stable-x86_64-pc-windows-msvc）
- MSVC 2022 Build Tools + Windows SDK 10.0.26100
- **cargo 必须走 `rsproxy.cn` 镜像**（官方源 26KB/s，镜像 2.4MB/s），已写入 `~/.cargo/config.toml`
- **GitHub 直连时通时断**，下大文件优先 `winget`（~15MB/s），别手 curl
- Python 3.13 为主（脚本零第三方库）；`C:/Python314/python.exe` 另装了 pymupdf，给 PDF 用
- Ollama 0.40.16，端口 11434，路径 `C:\Users\kingb\AppData\Local\Programs\Ollama\ollama.exe`
- GPU：RTX 4060 Laptop 8GB + 32GB 内存；已装模型 qwen2.5:7b / qwen3:4b / qwen3.5:4b / qwen3.5:9b

### 3.2 本地模型实测边界（8GB 显存）

- **qwen3 系列必须传 `"think": false`**，否则每次多吐 190+ token，3s 变 26s
- 8GB 装不下 7b + 4b 同时加载（llama-server 直接崩），换模型前先 `keep_alive: 0`；**不要 `ollama stop`**，会把 serve 一起带崩
- **并发无效**：Ollama 默认串行推理，并发 1/2/4 都是 27s。要快只能减份数或换小模型
- `num_ctx` 要给足输出余量：4096 跑 5000 字 prompt 会被挤到失败；8192 会把 9b 挤出显存跑 CPU（59 分钟不返回）
- 模型能力分工（24 份人工标注样本，误差 ±8 个点不显著）：
  - 判**类型**：规则 87.5% > 模型 79.2% → 类型词典比模型可靠
  - 判**工作域**：7b 79.2% 最好；9b 类型只有 75%（越大越差）
  - **视觉**：只有 qwen3.5 有 vision；9b 图片 4/4、扫描件 PDF 2/2，4b 是 3/4、1/2
- 模型最大毛病：**没有正文也硬猜，24 份里 0 次说「不知道」**。任何「让模型兜底」的设计都会被空话污染

### 3.3 已证伪的想法（有实测数据，别再试）

| 想法 | 实测结果 |
|---|---|
| 用存放目录语义救分类 | 306 份在「归档」下、227 份在「归档\下载」零语义目录；96 份判不出里靠目录只救回 3 份 |
| 固化一份通用事项类目清单 | 用户已明确否决：「不是一套固化的东西」 |
| 让本地模型给类目起名/归并 | 4b 起的组名是「部门/公司/组织名」「放之四海皆准的空话」，不可用；9b 一次性归并 40 候选可行但要 150s，179 候选分块要 12min |
| 让模型判 matter/org/person/doc/generic | doc/generic 变成垃圾桶，空话和真事项分不开 |
| 两层「工作域 × 文档类型」正交 | 已整体废弃 |
| 并发提速 | 见 3.2，无效 |

### 3.4 值得原样搬到新方案的三条工程红线

这三条是踩过坑换来的，与分类算法无关，重写时建议照搬：

1. **迁移永不破坏**：`复制 → SHA-256 校验 → 源文件进隔离区`，永不覆盖、永不直删、可整批撤销（`tools/restore_batch.py` 已验证）
2. **同名处理**：目标已存在就加序号，扩展名不同不算撞名；目录名清洗规则 TS 与 Rust 必须逐字一致（否则预览的树和真建出来的目录不一样）
3. **同一文档多版本**：全部版本都归档（一份不丢）、落盘时规范化命名（`V1.docx` → `(v1).docx`）、列表只折叠成一行、字节相同的副本只标注不删。红线：**日期不是版本号**（`…-2026.8.4.pptx` 改成 `(2026-08-04)` 会被当成有多个日期版本）；**同主名不同扩展名不能一律并族**（`detail.html/.js/.css` 是三个文件）
