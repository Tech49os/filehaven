# 文档分类方案 · 规格 v1.0

> 目标：把「预置词典把文件硬塞进固定类目」改造成「**从文件自身涌现类目 → 人确认方案 → 按方案归类**」的通用文档处理工具。
>
> 第一原则：**代码里不允许出现任何行业词**（钻采院、AI大赛、油化厂、智能工厂……）。
> 这些必须从文件自身涌现。唯一允许内置的是**语言级通用词**（方案、汇报、附件、副本、项目组、公司）——换任何行业都适用。

---

## 一、为什么必须改

现状（v0.2.1）是 `classifier.ts` 里写死的 9 个工作域 + 10 个文档类型词典。真实 450 份文件上的后果：

| 现象 | 数量 | 根因 |
|---|---|---|
| 全挤进「智能工厂平台」 | 178（39.5%） | 类目粒度太粗，一类里塞着 8 件互不相干的事 |
| 判不出项目按默认值填 | 61 | `DEFAULT_WORKSTREAM` 硬兜底 |
| 其中静默自动归档 | 58 | 兜底置信 0.74 > 阈值 0.7 |
| 只判到一级没二级 | 143 | 类型判不出就挂一级节点 |
| 完全判不出 | 96 | 文件名无信息 |

**核心问题不是判定算法不准，而是「类目表本身是拍脑袋定的」。**
你真实在办的事是「技术谱系、AI大赛、人工智能推进会、中期工作会、梯度培育、钻采院高温高压……」，
而系统给你的是「智能工厂平台、部门管理、商务采购、安全合规……」——两套语义对不上，怎么判都错。

---

## 二、四步流程

```
① 掌控全局        ② 初步打标签         ③ 确认分类方案        ④ 按方案整理
扫描 + 抽特征  →  涌现候选类目      →  人改名/删/合并     →  归类 + 迁移
                 模型归并命名          秒级重算归属
```

关键差别：**分类方案是「提案」，不是「结论」**。确认之前，不写任何文件、不建任何目录。

---

## 三、三层分工（原型实测结论）

我在你 450 份真实文件上跑了原型（`app/test/proto-topics.py`），实测：

| 层 | 职责 | 实测表现 |
|---|---|---|
| **算法** | 抽候选专名、粗分组 | 能抽出真事项：技术谱系、人工智能推进会、中期工作会、智擎海发版、逐浪数字蓝海、全栈工程师、油化厂、安环大屏。**但也会混进组织名（智能工厂技术室 24、生产智能化项目组 22）、人名（王一名 9）、英文噪音（detail）、切分残留（成本\|\|）** |
| **模型** | 清洗 + 归并 + 命名 | 必须参与。它要做的是「这几个候选其实是同一件事」「这个候选是部门名不是事项」「这组叫技术谱系」 |
| **人** | 裁决方案 | 看类名 + 代表文件，改到对为止 |

**结论：纯算法清不干净，纯模型太慢太贵，必须三层各司其职。这就是「通用」的真实代价。**

## 四、数据结构

```ts
/** 涌现出的一个事项 */
interface Topic {
  id: string
  /** 展示名，来自模型命名或用户改名 */
  name: string
  /** 一句话说明 */
  desc: string
  /** 别名（命中的专名候选），用于后续归属判定 */
  aliases: string[]
  /** 归入本事项的文件 id */
  fileIds: string[]
  /** 代表文件（确认时展示，3–5 个） */
  samples: { name: string; path: string }[]
  /** 来源：涌现 / 用户手工新建 */
  origin: 'emerged' | 'manual'
}

/** 一次归纳的完整提案 */
interface TopicProposal {
  topics: Topic[]
  /** 未能归入任何事项的文件（必须让用户看到，不能藏起来） */
  ungrouped: { id: string; name: string; path: string; hint: string }[]
  /** 统计：候选词数、模型是否参与、耗时 */
  meta: {
    candidates: number
    modelUsed: boolean
    degradedReason?: string
    elapsedMs: number
  }
}
```

**废弃字段**：`ws`（一级工作域）、`dt`（二级类型）。
**替代**：`topicId: string | null` + `tags: string[]`。

理由：单层分类下「类型」不再是目录层级，只作为标签存在。

## 五、算法：专名涌现

### 5.1 清洗
去扩展名 → 去 `附件N：` 前缀 → 去 `副本/最终版/修订版/定稿` → 去 `V1.0` / `20260908` / `2026.8.4` 等版本日期 → 去裸数字。

### 5.2 切段与候选
按 `- _ 空格 + · 、 ， ： 【】 （）` 切段。候选 = 整段（≤12 字）+ 段内 3–8 字 n-gram。
n-gram 是必要的：`智造领航逐浪数字蓝海` 需要能被切出 `逐浪数字蓝海`。

### 5.3 过滤
| 规则 | 参数 | 理由 |
|---|---|---|
| 文档频率下限 | DF ≥ 2 | 只出现一次的词不是「一件持续在办的事」 |
| 文档频率上限 | DF ≤ max(3, N×0.08) | 超过 8% 是部门名/公司名，区分力低（实测 `海油发展` 37/450=8.2% 是上限边缘） |
| 语言停用词 | 内置表 | 方案/汇报/报告/合同/清单/附件/模板/统计/汇总… |
| 组织后缀 | 内置表 | 项目组/技术室/工作组/团队/公司/部门/中心/事业部/研究院/分公司/办公室 |

**组织后缀处理的是「降级」不是「删除」**：`钻采院`也以「院」结尾，但它可以是真事项。
所以组织名只降权、标记 `isOrg`，最终由模型裁决。

### 5.4 最长匹配去重
`中海油信息科技有限公司科技技术谱系` 与 `技术谱系` 同时出现时，保留长串会重复计数。
规则：若 A ⊂ B 且 DF(B) ≥ DF(A)×0.85，则丢弃 A。**（0.85 而非 1.0，因为长串必然 DF 更小）**

### 5.5 排序与截断
`score = df × (1 - isOrg×0.6) × positionBonus`
`positionBonus`：候选在文件名首段出现记 1.0，中段 0.7，末段 0.5（末段常是落款）。

取 Top 80 送模型。

## 六、模型：归并 + 命名

**单次调用**，不是逐文件。

```
输入：80 个候选，每个带 DF、是否 isOrg、3 个代表文件名
输出（JSON Schema 约束）：
{
  "topics": [
    { "name": "≤8字", "desc": "一句话", "aliases": ["候选词1","候选词2"], "exclude": [] }
  ],
  "noise": ["判为组织名/人名/无意义噪音的候选"]
}
约束：
  - aliases 只能从给定候选里选，不能发明新词
  - 每件事项至少 1 个 alias
  - 事项数量 5–25，按真实业务密度定，不要凑数
```

**降级策略（模型不可用时）**：直接把 Top 12 非组织候选当类目，名字即候选词本身，标记 `modelUsed: false`，界面提示「未启用模型，类名由文件名直接给出，建议人工改名」。**不允许因此不可用。**

## 七、归属判定（确认后执行）

对每个文件算与每个事项的匹配分：

| 证据 | 分值 | 说明 |
|---|---|---|
| 文件名命中事项 alias | 0.90 | 强证据 |
| 目录路径命中 alias | 0.80 | 中证据（不预设，自动匹配） |
| 正文命中 alias | 0.72 | 弱证据，需第二证据才自动 |
| 正文命中事项关键词 ≥2 | 0.68 | 需人工 |

**≥0.85 自动归类；0.70–0.85 进待确认并预填；<0.70 进待确认且不预填。**
**绝对禁止兜底到某个默认事项。**

可选增强（沿用现有 smart 策略）：置信 <0.85 且有正文的文件，送本地模型在**已确认的事项清单内**二选一或「无法判断」。不新增类目。

## 八、标签体系（四类，与行业无关）

| 类别 | 来源 | 例 |
|---|---|---|
| 文档性质 | 语言级词表 | 合同、方案、汇报、纪要、清单、报价、模板、制度、申请单 |
| 时间 | mtime | 2026、2026-09 |
| 相关方 | 专名涌现（机构） | 海油发展、信科、钻采院 |
| 人名 | 规则：2–4 字中文出现在 `-` 后或 `附件` 后 | 王一名、李龙朝 |

标签是**标签，不是目录**。用户可以按标签筛选，但文件只进一个事项目录。

`InductionStep` 改造为「涌现 + 模型命名」的进度页；分类树预览移到 TopicConfirm。

## 十、验收标准（TDD 依据）

1. 给定 450 份真实文件名，涌现结果包含 `技术谱系`、`人工智能推进会`、`梯度培育`、`逐浪数字蓝海`、`油化厂` 至少 5 个真实事项名
2. `智能工厂技术室`、`生产智能化项目组`、`信科公司` 被标记 `isOrg=true`
3. 最长匹配去重生效：结果中不同时存在 `中海油信息科技有限公司科技技术谱系` 和 `技术谱系`
4. 模型可用时，`逐浪数字蓝海` / `智造领航` / `AI大赛` 被归并为同一事项
5. 模型不可用时仍能产出提案，`modelUsed=false` 且有降级原因
6. 改类名/删类/合并后重算 < 50ms，文件总数守恒（不丢不重）
7. 判不出事项的文件 100% 进 `ungrouped`，不存在默认兜底
8. 源码中不存在任何行业词常量（用 grep 校验 `钻采|油化厂|AI大赛|智能工厂` 不出现在 core 的类目定义里）
9. 标签能自动打出：性质 + 时间 + 相关方 + 人名
10. 确认后的方案持久化，同一根目录再次扫描可复用（可「重新归纳」覆盖）

---

## 十一、明确不做

- 不做「目录名接管分类」（你已验证：`信科-网安` 里装的是简历，`安环培训` 里装的是成本表，目录不可靠）
- 不做二级「事项 × 性质」树，类型只做标签
- 不内置任何行业词表，也不提供「行业词表配置」入口（要通用就彻底通用）
- 不做多用户/云端，仍是本地工具
