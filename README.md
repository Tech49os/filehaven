# 文件管家 · FileHaven

**Windows 桌面上的文件归位工具。** 把堆在桌面、下载、微信文件夹里的文档和图片，按内容归到该去的地方。

所有处理都在本机完成，**文件一个字节都不上传**。

> 当前是 **alpha 公测阶段**，功能仍在补齐。请先看 [Releases 页面](https://github.com/Tech49os/filehaven/releases)
> 里的「已知限制」再决定是否在真实文件上使用。

## 下载

前往 **[Releases](https://github.com/Tech49os/filehaven/releases)** 页面，选最新版本：

| 文件 | 说明 |
|---|---|
| `FileHaven-X.Y.Z-win64-portable.exe` | 免安装绿色版，双击即用，想删直接删 |
| `FileHaven-X.Y.Z-win64-setup.exe` | NSIS 安装版，有开始菜单图标、可卸载 |

> 软件没有代码签名，首次运行会被 Windows SmartScreen 拦一下。点「更多信息 → 仍要运行」即可，
> 详细说明和 SHA-256 校验值都在 Release 页面里。

**系统要求**：Windows 10 1809+ / 11，64 位。本地大模型（Ollama）可选，不装也能用核心功能。

## 它解决什么问题

桌面、下载、微信文件夹的混乱是慢慢积累的：文件下下来随手一放，几个月后几百个文件混在一起，
按名字猜不出内容，按日期分完还是找不到。

文件管家做的事：读一遍文件内容（标题、正文、元数据），判断它属于哪一类，给出目标目录建议和理由，
你确认后它把文件搬过去。判断不准时明确说「不知道」，不硬猜。

**你始终是决策者。** 它推荐，你点确认。

## 能做什么

**引导三步**：选源区（要整理的文件夹）→ 选归档区（建议放在空间大的分区）→ 建目录结构。
目录结构可以让本地模型给两套不同维度的方案，也可以自己写；模型没起就走手动，不阻塞。

**整理台**：一次 12 份，每份带推荐理由。
`回车` 确认主推 · `1/2/3` 选备选 · `N` 新建目录 · `S` 暂缓 · `P` 先放着 · `↑↓` 换一份 · `Ctrl+Z` 撤销。
没有足够相似的目录时，它会说「待你指定」，而不是随便塞一个。

**待迁移 → 应用迁移**：按目标目录分组，显示份数与体积。同名自动错开 `_2`；
标注后被改过的文件，红块拦下不搬。

**浏览与查找**：按目录浏览归档区，按文件名或正文搜索。
图片和扫描件 PDF 可走本地视觉模型解读内容。

**目录体检**：自动发现该合并的同义目录（`2026年9月` ≡ `2026年/9月`）、该改名的文件、空目录，
一次性看完再决定。

**重新归类**：在浏览页右键，把归档区里的文件二次迁移到别的目录，按批次可撤销。

**增量监听**：空闲时做增量整理，不打断你正在做的事。

## 数据安全：不覆盖、不直删、可撤销

这是整个工具最核心的设计。

每次搬文件都是三段式：

1. **复制** 到目标位置——原文件此时仍在
2. **SHA-256 校验** 新副本与原文件逐字节一致，不一致立即中止
3. 原文件移入 **隔离区**——不是删除

搬错了点「撤销这次迁移」，逐字节还原。撤销有两道保险：新副本被人改过会拒绝、原位置已有同名文件也会拒绝。
宁可不动，也不覆盖你后来的东西。

删除同样走隔离区，代码里**没有任何调用回收站的逻辑**，更没有永久删除。
系统目录（Windows、Program Files 等）是不可放开的黑名单。

## 关于本地模型

模型只做两件事：**目录结构建议** 和 **图片/扫描件解读**。其余能力完全不依赖模型。

模型断开或没装时，这两个能力降级，界面会明确标注「未经模型复核」，不会静默失败、不会卡住。
默认对接本机 Ollama，模型和数据都不出本机。

## 开发

```
app-v2/            当前工程（本版全部代码）
app/               v0.2.1 老工程（只读保留，别再改）
发布/              可执行文件与安装包
历史归档/          旧文档（需求/设计/评测/方案演进）
spec/              规格与实施计划
bugfix/            各 bug 的修复说明
design/            UI 设计标准与效果图
验收清单_P4.md     12 条验收的怎么验 / 结果 / 证据
P4_执行状态.md     进度、偏差、环境坑（写代码前先读）
```

技术栈已定，未经许可不更换：**Tauri 2 + Rust · Vue 3 + TypeScript + Vite · SQLite；本地模型可选（Ollama）**。

```bash
cd app-v2
export PATH="$HOME/.cargo/bin:$PATH"
npm install --registry=https://registry.npmmirror.com   # 官方源在国内常拉不动
npm run app:dev      # 开发模式（真窗口）
npm run app:build    # 出安装包 → src-tauri/target/release/bundle/nsis/
npx vitest run       # 前端测试
cd src-tauri && cargo test   # 后端测试
```

端到端脚本在 `app-v2/test/`（纯标准库，零第三方依赖）：

| 脚本 | 用处 |
|---|---|
| `run-e2e.py` | 全段回归，落日志 + 时间戳数据目录 |
| `seed-m8.py` | 造语料 + 写库；`verify-kill` 核对强杀后标注是否落盘 |
| `e2e-migrate.py` | 迁移/撤销全流程与逐字节核对 |
| `cdp.py` | 通过 CDP 驱动 WebView2：读 DOM、发键盘事件、点击 |
| `shotp.py` | 截窗口成 PNG |

> 部分机器上注入的**键盘**事件送不进 WebView2（鼠标能进），所以用 `cdp.py` 驱动：
> 启动前设 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9222"`。

## 硬约定

- 归档根目录固定，扫描可全盘但系统目录强制黑名单
- 迁移三段式：复制 → SHA-256 校验 → 源文件入隔离区；永不覆盖、永不直删、可撤销
- 处理范围：文档 + 图片 + draw.io；音视频不做
- 仅 Windows
- 低置信不硬猜，进待确认队列
