# BUG-005 修复说明：已确认卡片布局加固与长路径省略

## 1. 复测结论（实施前）

按用户裁决「即使已有 `flex:0 0 auto` 也按未修复写完整规格」，实施前先用 CDP 对当前版本复测。结论：**卡片整体压缩确实已消除，但残余挤压仍然存在**，不能降级为纯回归：

| 窗口 | 标题块宽 | 徽章区高 | 绿色结果行高 | 卡片总高 |
|---|---|---|---|---|
| 1000px | 177.48px | 20px | 80.39px | 363.84px |
| 1280px | 167.48px | 20px | 80.39px | 363.84px |
| 1600px | 487.48px | 20px | 59.59px | 343.05px |

- `.mid :deep(.card){flex:0 0 auto}`（Workspace.vue:753-755）保留了：卡片不再被 flex 拉伸/压扁。
- 但在 1000/1280px 下，徽章区 `flex:0 0 auto` + `min-width:auto` + 无 `max-width`，实际占到 358px，标题块被挤到 **167–177px**（长文件名几乎全靠省略号）。
- 「已归到 <长路径>」没有独立的可收缩块，长路径直接把绿色结果行撑到 **80.39px（约 4 行）**，卡片总高被顶高 ~20px——这就是截图 3 里「文字挤在一起」的残余现象。
- 三档宽度下文本块两两只相交面积为 0，说明是**挤压 + 撑高**而非几何重叠；加固项仍必须完整实施。

## 2. 根因

1. **标题 / 徽章同一 flex 行且徽章不可收缩**：`.hd` 为 `display:flex`，`.state` 为 `flex:0 0 auto; min-width:auto`，宽徽章区先占宽度，`.nm` 只能被压到极窄；`gap:12px` 没有显式 `column-gap`，窄窗间距语义不稳定。
2. **结果行长路径无裁切**：`已归到 <b>{{ path }}</b>` 的 `<b>` 没有 `min-width:0`/`overflow:hidden`/行数上限，长路径自由换行，把绿色条撑成多行；`title` 也不在路径块上。
3. **`min-height:0` 用在了非滚动容器**：`.card` 与 `.body` 都写了 `min-height:0`，正好踩中项目「待迁移被压扁溢出」的坑——被压缩的子项不该拿到它，它只属于 `.mid` / `.left,.right` 这类真正 `overflow:auto` 的滚动容器。
4. **右侧已确认栏行高无下限**：`.drow` 只靠内容撑高，列表变长时缺少 `min-height` 与 `flex:0 0 auto` 的确定性基线。

## 5. 边界与遗留风险

- 显示缩放 125% / 150% 未单独量测；用户本次验收只要求 1000/1280/1600 三档宽度，缩放维度的覆盖由组件测试的 CSS 不变量 + 100% 实测共同承担，如后续纳入验收可复用脚本加 `deviceScaleFactor`。
- CDP 的长路径 / 多徽章 / 10 条数据是 DOM 注入加压（demo 数据集没有现成的超长路径），测完即还原；它验证的是 CSS 几何，不是后端数据链路。
- `-webkit-line-clamp` 依赖 WebView2/Chromium；此项目目标运行时就是 WebView2，已实测生效。
- 未做截图对照（截图 3 非本次交付材料），几何结论以 `getBoundingClientRect` 数据为准。
- 未触碰状态判定 / 撤销链路，BUG-008、BUG-009 的 token 与字号基线保持原样。
