# BUG-009 修复说明：浏览页字号与行高提升至可读基线

## 1. 问题根因

浏览页文件列表的实际字号由 `FileList.vue` 的 `<style scoped>` 写死，且与 BUG-008 已落位的尺度 token 完全脱节：

| 位置（修复前） | 原声明 | 可读基线 | 差距 |
|---|---|---|---|
| `.row` | `height: 32px; font-size: 12.5px` | ≥13px / 行高 1.6 | 字号不足，固定行高把内容压住 |
| `.cell.kind/.size/.time/.st` | `font-size: 11.5px` | ≥12px | 次要列不足 |
| `.tchip` | `font-size: 10px; line-height: 1.5` | ≥11px / 1.6 | chip 最小、行高也不足 |
| `Browser.vue:562-642` | 另一份 `.list/.row/.cell/.tchip` | — | scoped 不作用于子组件，是**从未生效的死代码**，却构成第二套字号标准 |

根因不是「字体渲染」而是**尺度来源分裂**：BUG-008 已在 `tokens.css` 定义 `--fs-file-name:14px / --fs-meta:12px / --fs-chip:11px / --lh-file:1.6`，浏览页却没有引用；同时列宽用 `minmax(0, 1fr)` 允许无限压缩，一旦字号上调就会挤爆 6 列，因此修复必须先定窄窗策略。

## 2. 改动范围

- `app-v2/src/components/FileList.vue`
  - `.row`：`font-size: 12.5px` → `var(--fs-file-name)`；新增 `line-height: var(--lh-file)`；`height: 32px` → `min-height: 36px`（行高由内容决定）；`padding: 0 10px` → `var(--pad-row-y) var(--pad-row-x)`；`gap: 8px` → `var(--gap-row)`。
  - `.cell.kind/.size/.time/.st`：`11.5px` → `var(--fs-meta)`。
  - `.tchip`：`10px` → `var(--fs-chip)`，`line-height: 1.5` → `var(--lh-file)`。
  - `.hint` / `.empty` 顺带收敛到 `var(--fs-meta)` / `var(--fs-file-name)`，使整个 `<style>` 块不再有硬编码字号。
  - 窄窗：网格列改 `minmax(180px,1fr) 64px 80px 104px minmax(150px,1.1fr) 80px`，行加 `min-width: 740px`，列表沿用 `overflow: auto`。
- `app-v2/src/pages/browser/Browser.vue`：删除 `:562-642` 整段重复的 `.list/.row/.cell/.tchip` 死样式，留一行说明注释。
- `app-v2/src/styles/tokens.css`：在 BUG-008 尺度 token 注释里补充 BUG-009 窄窗策略（横向滚动）。
- `app-v2/src/components/FileList.test.ts`（新增）：10 项测试（3 项列结构/交互回归守卫 + 4 项字号行高 token 断言 + 2 项 Browser 死样式静态检查 + 1 项窄窗策略注释检查）。

**未触碰**：模板结构、6 列顺序、排序/筛选、`activate/open/menu/tagClick` 事件、打开/定位/右键重新归类逻辑、Rust 后端、`spec/`、`bugfix/*.docx`。

## 3. 关键决策

1. **复用 BUG-008 token，不另立标准**：所有字号/行高/内边距/间隙都引用 `--fs-file-name`、`--fs-meta`、`--fs-chip`、`--lh-file`、`--pad-row-x/y`、`--gap-row`。`min-height: 36px` 是规格直接给定的下限（008 没有对应 token），`min-width: 740px` 与网格轨道宽度属于列布局而非字号，沿用原代码的像素轨道写法。
2. **窄窗取「横向滚动」，不隐藏列**：二选一中选横向滚动，因为它可以保持 6 列结构在任何宽度下都不变（规格「不改变列结构」），且 `.list` 本来就有 `overflow: auto`。行设 `min-width: 740px` 后，窄窗只会出横向滚动条，绝不缩字号硬塞。策略已写进 `tokens.css` 注释。
3. **先写红测再改样式**：happy-dom 无真实布局，`getComputedStyle` 拿不到可信排版值，因此组件测试采用「源码级断言」——检查样式块引用了 token 变量、且不存在任何 `font-size: Npx`；真实 computedStyle 由 CDP 量测补足。
4. **删死代码而非保留作参照**：`Browser.vue` 的 scoped 样式不作用于子组件 `FileList`，两份规则只会让后续维护改错文件；删除后字号标准唯一。
5. **CDP 用全路径选择器**：`.list .row`、`.list .row .cell.name .nm`、`.list .row .cell.kind`、`.list .row .cell.time`、`.list .row .tchip`。仅用 `.row` 会命中页面里另一个同名但 0 个 `.cell` 的元素，导致假数据（本次量测中确实遇到并已纠正）。

## 5. 边界与遗留风险

- **happy-dom 的测试是源码级而非渲染级**：字号断言检查 token 引用与「无硬编码 px」，不模拟真实排版；真实 computedStyle 已由 CDP 覆盖，但若后续有人把 token 值改成不达标数字，BUG-008 的 `ui-consistency.test.ts` 会拦住下限。
- **横向滚动条的出现门槛**：行 `min-width: 740px`，实测 1000px 窗口下列表可视宽 788px，刚好不滚；窗口再窄（如补测的 800px）会出横向滚动条。这是既定策略的代价，不是布局破损。
- **`.empty` 从 13px 变 14px**、`.hint` 保持 12px：属于顺带统一到 token 的视觉微变化，不涉及信息层级。
- **命名碰撞**：页面里另有非列表用途的 `.row`（0 个 `.cell`）；后续若在 CDP/测试里写选择器，必须用 `.list .row` 全路径。
- **CDP 数据为 stub 渲染**：IPC 返回值是最小伪造数据（1 行 2 标签），用于量测排版尺度；真实后端分页/字段不在本 bug 范围，未验证。
- Rust 后端未改动，未跑 cargo；e2e 打开/定位/右键重新归类未单独跑（这些逻辑一行未动，由组件事件测试守卫）。
