# BUG-008 修复说明：统一文件条目尺度 token 与按钮样式

## 1. 问题根因

`tokens.css` 只统一了颜色，没有统一尺寸/排版；字号、内边距、底色、圆角散落在各组件的 `<style scoped>` 里硬编码：

| 维度（修复前，CDP 实测） | 整理台 `.mid .card` | 待定区 `.list .row` | 待迁移 `.frow` |
|---|---|---|---|
| 底色 | `rgb(255,255,255)` | `rgb(245,245,247)`（灰底大行） | 有 / 无数据 |
| 内边距 | `16px 18px`（矮窗档） | `12px 14px` | `4px 6px` |
| 圆角 | `14px` | `14px` | `8px` |
| 文件名 | `15px / 600 / 21px` | `13px / 500 / 20.8px` | `12px` |
| 元信息 | `12px / 19.2px` | `11px / 17.6px` | `11px` |
| chip | `11px / 16.5px` | `10.5px / 15.75px` | `10px` |
| 间距 | `10px`（矮窗档） | `6px` | `8px` |

按钮是结构性漂移源：`grep -r "\.btn\s*{" src/components src/pages` 实际找到 **10 处**裸 `.btn` 定义（规格文档列了 5 处：FileCard / Workspace / Settings / PendingMigration / Browser，另有 Onboarding / DirSuggest / NewDirInput / Search / DirHealth）。更严重的是 **Parked.vue 根本没有 `.btn` 定义**，它的按钮落到浏览器默认样式（`2px outset`、无圆角、黑字），CDP 实测即可确认。

## 2. 改动范围

- `app-v2/src/styles/tokens.css`：新增 7 个固定名字的尺度 token（见第 3 节）。
- `app-v2/src/styles/shared.css`（新增）：唯一的按钮基线（`.btn` / `.primary` / `.ghost` / `.small` / `:disabled` / `:active`）+ 文件条目统一外壳 `.file-entry`。
- `app-v2/src/main.ts`：入口引入 `shared.css`。
- 三处文件条目根节点挂 `.file-entry`：
  - `FileCard.vue` → `class="card file-entry"`
  - `Parked.vue` → `class="row file-entry"`
  - `PendingMigration.vue` → `class="frow file-entry"`
  - 各自删除硬编码的底色/边框/圆角/内边距/间距/字号行高，只保留布局与状态特化。
- 10 处裸 `.btn` 定义全部删除，组件只保留场景特化覆盖（`.acts .btn` / `.nodir .btn` / `.donebar .btn` / `.foot .btn` / `.btn.ghost` / `.btn.small` / `.btn.mini` / `.btn.primary` 等）。
- `Settings.vue` / `DirHealth.vue` 的按钮原本「裸 `.btn` 即主色」，模板显式补 `primary` 类以保持蓝底白字。
- `Search.vue` 的搜索按钮保留 `padding: 0 16px / 13px` 场景覆盖，避免与输入框错高。
- `app-v2/src/ui-consistency.test.ts`（新增）：6 项红→绿断言。

未触碰：`glass.css`（毛玻璃归 BUG-011）、所有事件/命令/权限逻辑、按钮文案与顺序、Rust 后端。

## 3. 关键决策

1. **token 名字固定，数值取可读基线**（BUG-009 / BUG-005 直接复用）：

   | token | 最终值 |
   |---|---|
   | `--fs-file-name` | `14px` |
   | `--fs-meta` | `12px` |
   | `--fs-chip` | `11px` |
   | `--lh-file` | `1.6` |
   | `--pad-row-x` | `16px` |
   | `--pad-row-y` | `12px` |
   | `--gap-row` | `10px` |
   | `--r-item` | 沿用已有 `8px` |

2. **用全局 `.file-entry` 类而非新组件**：三处条目结构差异大（卡片 / 列表行 / 表格行），抽组件会重写模板和事件绑定，回归面太大；共享外壳 + token 已能让 computedStyle 对齐，也满足「同一 token 类名」的验收点。
3. **按钮只留一份基线**：全局 `.btn` 取 `6px 12px / 12px / --r-btn`；Settings / DirHealth 的默认主色用显式 `primary` 保留，而不是保留两份私有 `.btn`。
4. **待定区不再灰底大行**：`.row` 去掉 `--c-field` 背景，改由 `.file-entry` 提供 `--c-surface` + `0.5px --c-border` + `8px` 圆角；改名（捞回 / 移出 / 指定目录 / 备注 / 标签）逻辑与 DOM 完全未动。
5. **`--gap-row` 同时用于 flex 与 grid**：迁移页 `.frow` 原 `column-gap: 8px` 删除，改用统一 `gap: 10px`。

## 4. 验证结果

### RED（新增测试，修复前先跑）

`npx vitest run src/ui-consistency.test.ts` → **6 failed / 6**：

- token 未定义；三处未挂 `.file-entry`；`shared.css` 不存在；待定区仍是灰底；全局 `.btn` 基线不存在；10 个组件仍有裸 `.btn`。

### GREEN（修复后）

- `npx vitest run` → **27 files / 230 tests passed**（基线 224 + 新增 6）。
- `npx vue-tsc --noEmit` → 无输出，退出码 0。
- 静态检查：`grep -rE '\.btn\s*\{' src/components src/pages` 仅剩 4 处带前缀的场景特化（`.foot .btn` / `.acts .btn` / `.nodir .btn` / `.donebar .btn`），裸定义 0 处；全局 `shared.css` 恰 1 份。

## 5. 已知边界

- **CDP 只量到两处**：量算时待迁移页为空（`store.empty`，无 `.frow`），故实测覆盖整理台与待定区两处；PendingMigration 通过共享 `.file-entry` 类 + 组件源码断言覆盖，未做真实渲染量算。如需第三处，先给待迁移页造一条 confirmed 数据再量 `.mg .groups .group .flist-body .frow`。
- **视觉变化**：整理台卡片内边距 `20px 22px`（矮窗 `16px 18px`）→ `12px 16px`、圆角 `14px` → `8px`；引导页/目录建议页按钮从 `7~8px 14px / 13px` 收敛为 `6px 12px / 12px`。这些是为一致性主动收敛的尺度，不涉及交互或信息层级。
- 迁移页每行现在带 `0.5px` 边框，密集列表的视觉噪点略增；若后续要求更轻，可只把 `.frow` 边框改透明，但那样 computedStyle 会与另两处不同。
- 毛玻璃材质未处理，归 BUG-011。
- Rust 后端未改动，未跑 cargo 测试。
