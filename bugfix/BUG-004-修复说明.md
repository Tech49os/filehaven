# BUG-004 修复说明：清理 2-gram 伪词与 AI 体裁弱标签

分支：`bugfix/batch-004-010`（基线 HEAD `95c6f8f`）
规格：`spec/BUG-004-tag-quality.md`

## 一、问题与根因

1. **2-gram 跨词伪词**：`tag.rs::tokenize` 对 ≥4 字汉字段在整段之外逐字生成 2-gram。
   「服务要求说明书」被切成 `服务 / 务要 / 要求 / 求说 / 说明 / 明书`，其中「务要」
   跨词边界、不是词汇，污染筛选与推荐输入。原 `STOPWORDS`（22 条）无法覆盖这类组合。
2. **AI 体裁弱标签**：`deep_tag.rs` 的 `GENERIC` 只有 12 个泛词，且 prompt 只禁泛词，
   模型仍会输出「服务委托书」「说明书」「通知书」这类文档体裁/文件类型名。
3. **已落库脏数据无清理路径**：旧标签已写入 `tags` / `file_tags`，只改生成逻辑不会回溯。

按用户裁决，`Word` / `2026` / `2026-Q4` 是刻意设计的基础标签，保留不动。

## 三、关键决策与裁决

1. **规格内部矛盾的消歧**：spec §5 写「tests.rs:390-409 基础标签断言继续通过」，
   §4 又写「只改伪词相关预期」。该测试中的 `kw.contains("安全")` 正是由 2-gram
   产生的预期，而 `Word`/`2026`/`2026-Q3`/`kw.len()<=3`/`year_quarter` 是基础标签断言。
   取舍：基础标签断言全部原样保留，仅把 2-gram 派生断言改为整段词「安全检查报告」，
   并同步更新 `tokenize_basic_cases` / `tokenize_real_corpus` 的同类预期。

2. **2-gram 在标签侧删除、在推荐匹配侧保留**（`tokenize_for_match`）：
   先按 spec 删除标签侧 2-gram 后跑全量，`calibrate_thresholds_on_real_corpus`
   报「有分 0 / 396」，真实语料推荐命中归零，属明显回归。
   spec §6 只允许「白名单式 2-gram」且需另开 spec，因此本 bug **不恢复标签侧 2-gram**，
   改为把原 2-gram 兜底收口到仅供推荐对称匹配的函数：它不落库、不展示、不进标签词表，
   不引入词典，也不产生「务要」这样的可见标签。若将来连匹配侧也要去 2-gram，
   按 §6 另开 spec 做白名单。

3. **体裁词规则**：不引词库，用「泛词整词 + 体裁整词 + 体裁后缀」三档判定，
   生成侧与清理侧共用 `is_weak_topic`，避免规则漂移。整词判定保证「合同管理」
   这类主题词不被误杀；后缀判定覆盖「服务委托书」「项目说明书」。

4. **清理判定方式**：不硬编码伪词黑名单，而是按当前文件名用标签分词器重算合法
   keyword 整段词，删掉不在集合中的挂靠；topic 侧按 `is_weak_topic` 全局判定。
   单事务执行、重复运行返回 0（幂等）、`tag_locked=1` 的文件整体跳过，
   `user` 类标签与 `type`/`time` 基础标签不参与。

5. **可见入口**：优先实现了设置页「标签词表」卡片的「清理弱标签」按钮，
   调用后重拉词表，无需手工逐条删除。

## 五、已知边界与后续

- 一次性清理按**当前文件名**重算 keyword：若文件曾被重命名，旧的合法 keyword 也可能被清掉。
  这是回溯清理的可接受代价；如需保留，可按 tag id 白名单再做一轮（另开任务）。
- 体裁黑名单是枚举式（`GENRE_WORDS` / `GENRE_SUFFIXES`），出现新公文体裁需同步补充，
  不自动学习；刻意不引中文分词词典以避免词库维护工程。
- 推荐匹配仍使用 2-gram（仅内存对称匹配，不进标签）；它带来的计算量与旧实现一致，
  perf 用例在 300ms 预算附近偶发抖动，单跑通过即可判定非回归。
- `clean_bad_tags` 为一次性入口，可重复运行；清理结果在设置页用「已清理 N 条弱标签」提示，
  0 条时提示「没有需要清理的弱标签」。
