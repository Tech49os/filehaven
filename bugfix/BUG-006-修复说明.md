# BUG-006 同语义目录合并 · 修复说明

分支：`bugfix/batch-004-010`　基线 HEAD：`e43fcf2`　规格：`spec/BUG-006-semantic-dir-merge.md`

## 一、根因

目录按物化 `rel_path` 存成节点（`index::insert_dir` 以 `/` 切段建节点），`2026年9月` 与 `2026年/9月` 是两条合法且不同的记录。全链路只有「相似路径」的同父近似检测（`dir_health::analyze` 规则 3），没有跨层级的语义归一化、同义分组、合并执行与按批次撤销。

具体缺口：
1. 无归一化纯函数：日期层级写法差异（`年/月` 合并写 vs 分层写）、版本/草稿后缀、全半角与空格差异都无法对齐。
2. 无可解释建议：没有「归一化签名 + 差异点」的候选输出，也没有推荐保留方规则。
3. 无合并执行：已有 `migration::recategorize` 三段式搬移能力，但没有「一组多份、单批次、kind 可区分、失败显式记账」的批量入口。
4. 无专用撤销：`migrations.kind` 只识别 `migrate` / `recategorize` / `dir_health`，通用 `undo` 会把新批次按普通迁移处理（错误改状态、错误标 undone）。

## 二、复用底座

| 既有底座 | 复用方式 |
|---|---|
| `dir_health.rs::scan_report` | 照搬 `scan → rule → model → done` 四阶段与「模型不可用也发 model 阶段、降级不报错」骨架 |
| `dir_health.rs::apply_rename` / `undo_dir_health` | 复用「撞名错开、单事务落库、台账 + 按批次撤销」的编排纪律 |
| `migration.rs::recategorize` | 复用三段式（复制 → SHA-256 校验 → 旧副本入隔离区）与 `old_dir_id` 台账机制；提升为单批次 `kind='dir_merge'` |
| `migration.rs::undo` | 扩展 kind 拒绝逻辑，`dir_merge` 与 `dir_health` 一样必须走专用撤销 |
| `plan.rs::quarantine_path` / `unique_name` / `archive_dir_path` | 隔离区布局、同名 `_2` 错开、路径拼接全部走同一处定义，未另造 |
| `migrate.rs::sha256_of` / `copy_file` / `move_file` / `find_in_quarantine` | 文件系统三段式原语直接复用 |
| `suggest_dirs.rs::strip_version_suffix` | 版本/草稿后缀剥离直接复用，不另写规则 |
| 前端 `DirHealth.vue` / `core/ipc.ts` / `core/types.ts` / `core/events.ts` | 建议列表交互（扫描/采纳/忽略/撤销/阶段提示）沿用同一模式 |

## 四、关键决策

1. **单批次而非 N 个 recategorize 批次**：直接逐份调用 `migration::recategorize` 会产生 N 个 `kind='recategorize'` 批次，无法满足「同组按批次撤销」与 `kind='dir_merge'` 审计要求。因此复用其三段式机制与台账列，在 `dir_merge::apply_merge` 里提升为**一个** `dir_merge` 批次、每份一个独立事务。
2. **归一化先整串后切段**：若先按原路径切段，全角斜杠 `／` 不会被切开，日期层级与版本后缀都归一不了。实现固定为「折宽 → 去空白 → 切层级 → 段内归一 → 日期展开」。
3. **层级语义优先于文件数**：推荐目标先比原始路径段数（分层写法更清晰），再比文件数、创建时间。签名里保留段顺序，`9月/2026年` 与 `2026年/9月` 永不成立同组。
4. **超时组不静默丢弃**：超过 50 份的组不进候选，但在报告 note 里写明「已跳过超过 50 份文件的超大组」。
5. **撤销不直删**：新位置副本移入隔离区 `_undo/<name>`（按 `unique_name` 防覆盖），隔离区原件按 SHA-256 校验后还原；同名冲突或哈希不一致直接拒绝，不覆盖任何文件。
6. **empty 标记不删记录**：只改 `is_empty`，不删 `archive_dirs` 行、不动磁盘空目录；撤销后按 `old_dir_id` 取消标记。

## 六、边界与遗留风险

- 只做低手动触发扫描，不进启动流程；模型走 `ModelGate` 0ms 非阻塞抢闸，深读占用时直接降级，不抢闸也不等待。
- 单组上限 50 份；更大规模需用户拆分（报告 note 会提示）。模型不可用时只有确定性规则候选，标注「未经模型复核」。
- 不碰磁盘空目录删除，隔离区布局沿用既有约定；已标记 empty 的目录不再参与后续扫描。
- `migrate::move_file` 的跨盘兜底沿用既有实现（复制校验后删源）；若隔离区目标已存在同名且哈希相同，极端情况下的覆盖语义属于共享底座既有行为，本 bug 未改动，列为遗留风险。
- 忽略状态存于浏览器 `localStorage`，仅影响本机当前浏览器；换设备/清缓存后需要重新忽略。
